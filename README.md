# 月灵 Bot 使用手册

命令前缀：无（直接发命令即可）

**匹配方式说明**

- **精确** — 整条消息只含这个词才触发，不会误触
- **命令** — 消息开头匹配，后面可带参数
- **关键词** — 消息中包含此词即触发
- **正则** — 正则表达式匹配
- **被动** — 无需触发词，自动响应特定事件

## 加群审核

> 需要 **管理员 / 群主** 权限，每个群单独配置

加群申请的**验证理由**命中关键词时自动处理：命中拒绝词→拒绝，命中通过词→通过，**拒绝优先**，都不命中则留管理员人工处理。

> 通过词 / 拒绝词均为**覆盖式**设置：填写即整体替换该群的词表，留空则清空。

| 命令 | 匹配 | 说明 |
|------|------|------|
| `加群审核` | 命令 | 查看本群通过词（白名单）/ 拒绝词（黑名单） |
| `加群白名单 词1,词2` | 命令 | 覆盖通过词（逗号分隔多个）；填 `*` 表示任意理由放行 |
| `加群白名单` | 命令 | 留空=清空通过词 |
| `加群黑名单 词1,词2` | 命令 | 覆盖拒绝词；留空=清空 |

## 群规则

群规则会注入到 **AI 的系统提示词**中，用来约束月灵在本群的行为。例如添加「不准说脏话」「回复时不超过 100 字」等规则后，AI 对话会遵守这些约定。

| 命令 | 匹配 | 权限 | 说明 |
|------|------|------|------|
| `群规则` | 命令 | 无 | 查看当前所有规则及其 ID |
| `添加群规则 <内容>` | 命令 | 管理员 | 新增一条 AI 行为约束规则 |
| `删除群规则 <ID>` | 命令 | 管理员 | 按 ID 删除规则（ID 从群规则列表获取） |

## 素材上传

发送命令时**同时附带图片**，或**引用含图片的消息**，支持一次多张。相同图片重复上传会提示「已收录」。

下面的随机图片 / 4合1 类目由 `config.toml` 的 `[[image.entry]]` 配置表驱动（不配则用内置默认表），每条的 `arg` 决定要不要带词；加新类目只改配置、帮助自动跟随，详见末尾「配置文件」。语录 / 表情是独立功能，不在该配置表内。

**① 直接加图**（`arg=false`，文件名用图片 hash）：

| 命令 | 存入文件夹 |
|------|-----------|
| `添加老婆 / 添加老公 / 添加福瑞 / 添加龙图` + 图片 | 老婆 / 老公 / 福瑞 / 龙图 |
| `添加杂鱼 / 添加沙雕图 / 添加美少女 / 添加ba` + 图片 | 杂鱼 / 沙雕图 / 美少女 / ba |

**② 须带名字 + 图**（`arg=true`，4合1 类目，文件名存「名字_hash」，网格里用名字当标签）：

| 命令 | 存入文件夹 |
|------|-----------|
| `添加吃的 <名字>` + 图片（如 `添加吃的 麻辣烫`） | 吃的 |
| `添加喝的 <名字>` + 图片 | 喝的 |
| `添加玩的 <名字>` + 图片 | 玩的 |
| `添加水果 <名字>` + 图片 | 水果 |

**③ 语录 / 表情**（独立功能，关键词可选，用于后续检索）：

| 命令 | 存入文件夹 |
|------|-----------|
| `添加表情 [关键词]` + 图片 | 表情（按关键词索引，空格触发可查） |
| `添加语录[昵称]` + 图片 | 语录（按群+昵称索引；默认可省略命令与昵称间的空格） |

## 表情包生成

> 需要启动 meme-generator-rs 服务（`config.toml` 中配置 `meme_server`）

支持 **130+ 种**表情包模板，直接发关键词触发。

| 命令 | 匹配 | 说明 |
|------|------|------|
| `<关键词>` | 命令 | 生成对应表情包，如 `摸摸`、`亲亲`、`字符画 文字` |
| `<关键词> @某人` | 命令 | 用 @用户的头像生成（适用于需要人物的模板） |
| `<关键词> [文字]` | 命令 | 附带文字内容（适用于需要文字的模板） |
| `头像表情包` | 精确 | 查看所有头像类模板列表（图片） |
| `表情详情 <关键词>` | 命令 | 查看指定模板的关键词、参数要求和预览图 |
| `表情帮助 <关键词>` / `表情示例 <关键词>` | 命令 | 同表情详情 |
| `随机表情` | 命令 | 随机挑一个模板，用自己头像生成 |
| `随机表情 @某人` | 命令 | 随机挑一个模板，用 @用户头像生成 |

**图片来源优先级**：消息附图 > 引用消息中的图 > @用户头像 > 发送者头像。
需要图片但未提供图片或 @用户时，自动使用发送者头像。

需要文字的模板若未提供，自动使用模板默认文字。

### 月灵自制表情包

`月灵表情包` / `自制表情包` 是 yueling-go 自有的纯 Go 模板插件，与上述外部
`meme-generator-rs` 服务相互独立。模板和素材会按需逐步加入；外部服务不可用时，
自制模板仍可正常工作。

所有需要图片的自制模板使用同一套来源规则：消息附图 > 引用消息中的图 >
@用户头像 > 发送者头像；不提供图片或 @用户时自动使用发送者头像。

| 命令 | 说明 |
|------|------|
| `单身` / `单身打算` / `暂时不恋爱` / `没有恋爱的打算` + 图片 / `@某人` | 保留模板上半部分，用图片或头像替换下半部分，固定文字不变 |
| `嘲笑` + 图片 / `@某人` | 保留九宫格和黑色分隔线，把中心格替换为附件、引用图片或用户头像 |
| `老人微笑 上句\|下句` | 给上下两张照片各添加一行底部字幕；不传文字时使用示例文案 |
| `蜘蛛人戴眼镜 上句\|下句` | 把两段文字自动换行、缩放并居中放入右侧上下区域 |
| `游戏王 标题\|说明` + 图片 / `@某人` | 将标题、图片和说明分别放入游戏王卡牌的三个内容区域 |
| `握手洗手 第一段\|第二段\|第三段` | 按左上、右下、左上的位置给握手洗手三联图添加文字 |

## 自然语言提醒

直接对月灵说人话即可，例如：

- `月灵 明天下午三点提醒我交材料`
- `月灵 每个工作日九点提醒我打卡`
- `月灵 每周一和周四晚上提醒我健身`
- `月灵 把提醒 12 改到下周一` / `把提醒 12 推迟半小时`

保留 `我的提醒` 和 `取消提醒 <ID>` 两个确定性查询/取消命令。

## 个人资料与长期记忆

个人资料与记忆统一通过 AI 管理：

- `月灵 以后叫我阿七`、`我住在上海`、`我的时区是 Asia/Shanghai`
- `月灵 记住我不吃香菜`
- `月灵 我的资料是什么`、`你记得我什么`
- `月灵 删除我的位置`、`忘掉记忆 12`

称呼、位置、时区、回复风格等用户明确设置的资料优先于 AI 推断记忆。长期记忆会在 PostgreSQL 中用中文全文检索召回；密码、验证码、证件号、银行卡和密钥不会被自动保存。

## AI 对话

| 触发方式 | 匹配 | 说明 |
|---------|------|------|
| `@月灵 <内容>` | 被动 | 触发 AI 对话 |
| `月灵 <内容>`（消息开头） | 关键词 | 触发 AI 对话 |
| 群内消息密度达到阈值 | 被动 | 月灵自动参与聊天 |

5 分钟内的对话自动续接上下文（多轮对话）。翻译、改写、摘要、代码解释等纯文本任务由 AI 直接回答；只有真实外部动作才调用 Tool。Tool 包括天气、搜索、航班/火车、计算、汇率、自然语言提醒、待办、群聊统计、个人资料与记忆、订阅、知识库及受权限控制的群管理等。群插件在 WebUI 中被禁用时，对应 AI Tool 也会同步禁用。

### AI 会话与长期记忆

| 说法 | 作用 |
|------|------|
| `月灵 新对话` | 立即清空本群内自己的短期对话上下文，不调用模型 |
| `月灵 你记得我什么` | 查看 AI 自动保存的长期偏好 |
| `月灵 忘记第 N 条记忆` | 删除自己指定的一条长期偏好 |
| `月灵 清空我的长期记忆` | 清空自己的长期偏好，并重置当前对话 |

这些控制语句由 Bot 本地确定性执行，不消耗 AI 调用次数，也不会影响待办、积分或个人资料。

### 定时群聊日报

群管理员可以设置每天自动总结最近的群聊内容：

| 命令 | 作用 |
|------|------|
| `群聊日报 21:30` | 每天 21:30 总结最近 80 条消息 |
| `群聊日报 21:30 100` | 指定总结最近 100 条消息 |
| `群聊日报 现在 80` | 立即生成一次，不修改定时设置 |
| `群聊日报` | 查看当前设置 |
| `群聊日报 off` | 关闭日报 |

日报会输出今日话题、重要信息和待跟进事项。聊天内容仅作为待总结数据处理，不会被当作系统指令执行。

### RSS / Atom 订阅中心

群管理员可以把公开信息源接入群聊。月灵每 10 分钟检查一次更新，支持 RSS 2.0、Atom 与 RSS 1.0，也可以订阅 GitHub Releases 的 `.atom` 地址或 RSSHub 生成的公开路由。

| 命令 | 作用 |
|------|------|
| `订阅添加 <URL> [名称]` | 添加信息源；以当前最新内容为基线，不补发历史文章 |
| `订阅B站视频 <UID/主页> [名称]` | 订阅 UP 主的新投稿 |
| `订阅B站动态 <UID/主页> [名称]` | 订阅 UP 主动态 |
| `订阅B站直播 <房间号/链接> [名称]` | 订阅直播间开播 |
| `订阅X <用户名/主页> [名称]` | 订阅 X 用户发推 |
| `订阅列表` | 查看本群全部订阅及 ID |
| `订阅状态` | 查看异常源、待推送条数和静默设置 |
| `订阅暂停 <ID>` | 暂停单个源并清理它尚未发送的内容 |
| `订阅恢复 <ID>` | 恢复单个源，并在下一轮重新检查 |
| `订阅静默 23:00-08:00` | 夜间继续抓取，静默结束后合并推送 |
| `订阅静默 off` | 关闭静默时段 |
| `订阅检查` | 立即检查；非静默时段同步推送新内容 |
| `订阅删除 <ID>` | 删除指定订阅 |

平台快捷订阅由 `[feed].rsshub_base` 指向的 RSSHub 实例提供。公共演示实例可能限流、触发 Cloudflare 验证或受网络影响；本仓库的 Docker Compose 会自动启动带 Chromium 的自建 RSSHub，并让 Bot 使用 `http://rsshub:1200`。非 Docker 部署可设置 `[tools].proxy`，或自行部署 RSSHub 后修改 `rsshub_base`。B站投稿路由存在反爬风险，动态路由通常更稳定。

如果要把 RSSHub 手工合并进旧版或自行维护的 Compose 文件，必须同时加入四部分：`rsshub` 与 `rsshub-redis` 服务、Bot 的 `YUELING_FEED_RSSHUB_BASE=http://rsshub:1200` 环境变量、Bot 对 `rsshub` 的健康依赖，以及顶层 `volumes` 中的 `rsshub-redis-data:` 声明。合并后先执行 `docker compose config --quiet`；该命令通过后再执行 `pull` 或 `up`。

RSSHub 的可选账号凭证统一放在项目根目录 `.env.rsshub`（参考 `.env.rsshub.example`）。X 用户时间线推荐只配置登录 `x.com` 后 Cookie 中的 `TWITTER_AUTH_TOKEN`；也可改用 X Developer App 的 `TWITTER_CONSUMER_KEY` + `TWITTER_CONSUMER_SECRET`，两种方式二选一。B站动态默认由内置 Chromium 获取访客 Cookie；如果仍遇到源站 `-352` 风控，可在 `.env.rsshub` 添加 `BILIBILI_COOKIE_<登录账号UID>`，其值必须是浏览器请求中的完整 Cookie。

大陆网络中，RSSHub 容器访问 X 通常还需要独立代理。可在 `.env.rsshub` 设置 `PROXY_URI=http://host.docker.internal:7890`，并按 `.env.rsshub.example` 的 `PROXY_URL_REGEX` 只代理 X 相关域名，让 B站继续直连。

每群最多 10 个订阅，每个源单轮最多接收 5 条新内容。新条目和订阅游标会先在同一事务中写入 PostgreSQL 持久队列，再按群合并推送；QQ 发送失败、Bot 重启或处于静默期都不会丢更新。每条群消息最多合并 12 条，剩余内容留到下一轮。连续抓取失败会按 10、20、40 分钟逐级退避，最长 6 小时，成功后自动恢复正常频率，错误和下次检查时间可在 `订阅状态` 或 WebUI 查看。

普通订阅抓取仅允许公网 HTTP/HTTPS 地址，限制响应体大小，并会拒绝回环、私网、链路本地和云元数据地址；只有配置文件明确指定的 RSSHub 同源地址可访问内网。插件禁用期间只同步游标并清空待推送队列，恢复后不会刷屏补发。

### 群知识库问答

每个群拥有完全独立的资料库。管理员可以录入长期有效的文字资料，或从公网 HTML/纯文本网页导入正文；群员只有显式提问时才会触发 AI，不会在后台持续消耗调用量。

| 命令 | 作用 |
|------|------|
| `知识添加 [标题] \| <内容>` | 添加一条文本知识（群管理员） |
| 回复文字 + `知识添加 [标题]` | 把被回复内容保存到知识库（群管理员） |
| `知识导入 <URL> [标题]` | 安全抓取公网网页正文（群管理员） |
| `知识列表` | 查看本群专属及共享知识的 ID、标题和作用域 |
| `知识问 <问题>` | 检索本群专属资料和所有群共享资料，并生成带 `[知识#ID]` 引用的回答 |
| `知识删除 <ID>` | 删除指定知识（群管理员） |

知识条目还可以在 WebUI 或通过管理员自然语言设置最多 10 个“快捷触发词”。例如给下载地址知识设置 `ae下载` 后，群友只需发送完全相同的文字，Bot 就会立即回复该条内容或来源链接：不需要 `@月灵`、不调用 AI，也不会继续触发复读等兜底功能。WebUI 可选择“所有群共享”或某个具体群；检索会合并共享知识与本群知识，同名快捷词由本群专属条目优先。

每个群专属空间和共享空间各最多 100 条，单条最多 12,000 字。网页导入沿用公网 URL 与响应体限制；检索结果会作为不可信参考资料交给模型，回答被要求只依据当前群可用的命中知识，不足时明确说明，不会检索其他群的专属资料，也不会把网页里的提示词当成指令。

AI 也可以调用当前 NapCat 连接上的 QQ 动作：

| 示例 | 效果 |
|------|------|
| 回复一条消息并发送 `@月灵 把这条设精` | 将被引用消息设为精华 |
| `@月灵 把我的群名片改成 今天不加班` | 修改自己的群名片 |
| `@月灵 给我一个 摸鱼冠军 的头衔` | 设置自己的专属头衔 |
| `@月灵 戳一下 @某人` | 戳一戳被提及成员 |
| `@月灵 撤回刚才那条广告` | 查询近期消息并按真实消息 ID 撤回 |
| `@月灵 禁言刚才说脏话的人十分钟` | 查询近期消息并按真实用户 ID 禁言 |

`get_chat_history` 会为每条记录提供消息 ID 和用户 ID，供撤回、禁言等 QQ 动作继续调用。所有群友都可以使用 AI 撤回和禁言工具；普通成员只能修改自己的群名片和头衔，群管理员、群主及超级管理员可以修改本消息中额外 `@` 的第一个成员。实际动作仍要求 Bot 账号在群内拥有相应 QQ 权限。

`zssm` 等用户 URL 抓取只允许访问公网 HTTP/HTTPS 地址，并限制响应体积；回环、私网、链路本地及云元数据地址会被拒绝。

### 图片类目配置表 `[[image.entry]]`

随机图片 / 4合1 / 外链 三类图片命令由配置表驱动。**不配则用内置默认表**（龙图/福瑞/老公/老婆/沙雕图/杂鱼/美少女/ba + 吃喝玩乐 4合1 + 随机猫猫）；**一旦填写则整体覆盖**默认表。加一个类目只改配置，帮助与命令自动跟随。

每条 entry 两个维度正交：`kind` 管**调用方式**，`arg` 管**添加规则**。

`kind`（调用方式）：

| kind | 调用 | 必填字段 |
|------|------|---------|
| `single`（默认，可省） | 随机发一张 | `folder` `call` |
| `grid` | 挑 4 张拼 2×2 网格、按名字列菜单 | `folder` `call` `add`（且 arg=true） |
| `external` | 发外链 URL | `call` `url` |

`arg`（添加规则，**看这一项就知道怎么加**）：

| arg | 添加方式 | 文件名 |
|------|---------|--------|
| `false`（single 默认） | `添加X` + 图片，直接加 | 图片 hash |
| `true`（grid 默认/强制） | `添加X <名字>` + 图片，名字必填 | `名字_hash`（4合1 用名字当标签） |

> 省略 `arg` 时按 kind 取默认（grid→true、single→false）；`grid` 不能 `arg=false`。`single` 也能配 `arg=true` 做「带名字标签的随机图」。
> `external` 可选 `pick`：接口返回 JSON 时按路径取图，留空则把 `url` 的响应本身当图片。语法：`a.b` 取字段、`[N]` 取第 N 个、`[*]`/`[random]` 随机一个（**数组必须写下标**，如 `data[*].url`）。

```toml
# single：随机发一张，直接加图
[[image.entry]]
folder = "龙图"
call   = ["龙图", "龙图攻击"]
add    = "添加龙图"
arg    = false

# grid：4合1 网格，添加须带名字（如「添加吃的 麻辣烫」）
[[image.entry]]
folder = "吃的"
call   = ["随机吃的", "吃啥", "吃什么", "来点吃的"]
add    = "添加吃的"
kind   = "grid"
arg    = true

# external：外链，响应直接是图
[[image.entry]]
call = ["随机猫猫", "来点猫猫"]
kind = "external"
url  = "http://edgecats.net/"

# external：接口返回 JSON，从 data.url 取图（data 是对象）
[[image.entry]]
call = ["来只狗", "随机狗"]
kind = "external"
url  = "https://api.example.com/dog"
pick = "data.url"

# external：列表 + 相对路径——[*] 随机取项，base 补全站点前缀
[[image.entry]]
call = ["随机插画", "来点插画"]
kind = "external"
url  = "https://pln.yuelili.com/api/v1/artworks/random?limit=24"
pick = "data[*].url"               # data 列表随机一项 → .url 得 /api/v1/files/xxx.png
base = "https://pln.yuelili.com"   # 补成完整地址再发
```

> `external` 可选 `base`：`pick` 取到相对路径（`/...`）时拼站点前缀；取到的已是完整 `http(s)` 地址则忽略。

> 语录、表情因检索逻辑特殊（群隔离白名单 / 关键词空格触发），是独立插件，不在此配置表中。

供外部系统通过 HTTP 让 Bot 主动发群 / 私聊消息。配置 `[http_api]`（`addr` 留空=关闭）后，`POST /api/send` 即可发送，请求体为 OneBot v11 段数组，响应返回实际 `message_id`。

`skills/notify-task-done/` 是一个调用该 API 的示例 Claude Code skill：任务完成时推送 `✅ … 已完成` 通知，端点 / 密钥全走环境变量，可直接参考或拷贝使用。

## WebUI 管理后台

启用 `[webui]` 后，Bot 进程会同时启动一个密码保护的管理后台。后台包含运行总览、每群插件策略、全局/按群命令调用统计、AI 默认与群级对话风格、群消息发送、群聊日报调度、RSS/Atom 订阅、群知识库、AI 好感度和长期记忆管理。运行期管理数据统一写入 PostgreSQL，不会写回 `config.toml`。

| 页面 | 用途 |
|------|------|
| 运行总览 | 查看 Bot 连接、群聊、插件、日报、订阅和 AI 数据概况 |
| 插件策略 | 按群启用或禁用能力，也可批量应用到所有群 |
| 调用统计 | 查看所有群汇总或单群最近 7/30/90 天命令趋势、独立用户和常用命令排行 |
| 消息中心 | 组合文字、艾特和图片并发送到指定群 |
| AI 对话风格 | 编辑全局默认提示词，并按需为特定群设置独立覆盖 |
| 群聊日报 | 可视化设置每天的发送时间和消息采样数量 |
| 订阅中心 | 按群管理信息源、静默时段、持久队列和源健康状态 |
| 群知识库 | 分别管理所有群共享知识与群专属知识，录入文本或导入网页 |
| 关系引擎 | 查询及调整群成员的 AI 好感度 |
| 长期记忆 | 检索、删除或按用户清空 AI 自动提取的偏好 |

WebUI 不需要单独设置 token，登录只看 `[webui].password`。连续输错密码会被短暂限流；如果页面提示“请先登录”，打开 `/login` 或重新登录即可。如果提示“密码错误”，检查 `config.toml` 里的 `[webui] password`。

NapCat 的 token 是另一套鉴权，只影响 Bot 和 NapCat 的 WebSocket 连接：`[napcat].token` 必须和 NapCat 网络配置里的 access token 一致。建议始终设置强 token；反向 WS 留空时不会做身份校验，但只接受回环或私网来源，并拒绝跨站浏览器连接。

## 部署

### 本地运行

```bash
cp config.example.toml config.toml   # 复制示例配置并填写
task run                             # 构建 WebUI 后启动 bot
```

### Docker

```bash
cp config.example.toml config.toml   # 填写配置
task docker:up                       # 校验配置，构建并启动完整服务栈
```

`docker-compose.yml` 默认使用 `ghcr.io/yuelioi/yueling-go:latest`，服务器可执行 `docker compose pull && docker compose up -d` 直接更新；执行带 `--build` 的 `task docker:up` 时则会从当前源码构建。Compose 会启动 Bot、PostgreSQL、NapCat、meme-generator-rs、RSSHub 及其 Redis 缓存。Dockerfile 内会执行前端构建并把 `webui/dist` 打进运行镜像。结构化数据全部进入 Compose 内的 PostgreSQL；数据库直接使用带 `zhparser` 的 `zhparser/zhparser:alpine-16` 镜像，无需在本机编译 PostgreSQL。该上游镜像仅发布 `linux/amd64`，Compose 已固定平台，ARM 版 Docker Desktop 会自动通过模拟运行。聊天中文全文索引和词云分词都在 PG 内完成，PG 默认不向宿主机暴露端口。启用 `[webui]` 后，可通过 `http://127.0.0.1:9080` 访问。

生产部署请在项目目录的 `.env` 设置数据库密码：

```dotenv
POSTGRES_PASSWORD=请替换为强密码
```

Compose 会通过 `PGPASSWORD` 把密码单独传给 PostgreSQL 驱动，不会把密码拼进连接 URL，因此密码可以包含 `@`、`:`、`/` 等 URL 保留字符。

#### 从旧 SQLite 升级

旧版 `data/yueling.db` 可一次性导入 PostgreSQL。迁移前先停止旧 Bot，确保迁移期间没有新写入：

```bash
cp data/yueling.db data/yueling.db.backup
docker compose stop bot
docker compose up -d postgres
docker compose build bot
docker compose run --rm --no-deps --entrypoint ./migrate-sqlite bot \
  --sqlite /app/data/yueling.db
docker compose up -d bot
```

迁移器会逐表输出读取行数、忽略已经存在的主键/唯一键，并在导入后校正 PostgreSQL 自增序列，因此意外中断后可以重新执行。确认新 Bot 和 WebUI 数据正常后再归档旧 `.db`，不要提前删除。

旧版自动回复不再导入或转换，升级时会直接删除旧回复表。需要保留的内容请在对应群的知识库中重新添加，并按需设置快捷触发词；例如为下载地址知识填写 `ae下载`。SQLite 迁移器同样会跳过旧回复表。

meme-generator-rs 服务**默认随 bot 一起启动**。启动后在 `config.toml` 中设置：

```toml
[tools]
meme_server = "http://meme:2233"   # Docker 内服务名固定为 meme
```

不需要表情包生成时，可单独只启动 bot：

```bash
task docker:bot
```

#### NapCat 连通

| NapCat 位置 | config.toml `url` 填写 |
|------------|----------------------|
| 宿主机（Linux） | `ws://host.docker.internal:<NapCat WS 端口>/...` 或宿主机 IP |
| 宿主机（Mac/Win） | `ws://host.docker.internal:<NapCat WS 端口>/...` |
| 同 compose 网络 | `ws://napcat:3001/...` |

反向 WS 模式（NapCat 连 bot，推荐）：设置 `serve = ":9077"`，再在 NapCat WebUI 配置客户端地址 `ws://bot:9077/onebot/v11/ws`；Compose 已默认映射该端口，无需额外修改。

    ├── fonts/
    │   ├── Mamelon.otf
    │   └── sakura.ttf
    ├── themes/
    └── copywriting.json
