# 月灵 Bot 使用手册

命令前缀：无（直接发命令即可）

## 后台配置

后台配置按功能分发，不再使用集中式配置管理：

- **AI 模型**：添加模型、声明能力、管理共用账号与凭据，以及测试模型。
- **AI 配置**：为各功能选择模型、调整限流/上下文/好感度，以及对话风格与缓存用量。
- **订阅**：订阅中心（信息源与推送策略）与订阅配置（RSSHub）。
- **插件**：群级策略与全局开关。
- **B站**：私信监控与回复、账号配置（Cookie）。
- **图片与打包**、**工具与服务**：图片转换/类目、打包限制，以及天气、搜索、代理和表情包服务。
- **连接配置**：QQ 连接与消息接口。
- **系统配置**：机器人名称、管理员、命令前缀、后台和数据库连接池；启动信息也在这里查看。

**群管理总览** 汇总全部群的订阅异常、日报、知识库、插件禁用、AI 风格和审核模式，可按群名或群号筛选并进入对应功能。订阅与知识库默认展示全部条目，插件、风格、审核、日报默认展示群配置列表；聊天洞察先按群列出统计。全局默认 / 共享空间与“全部查看”是不同范围，编辑和消息发送始终指向明确群。Bot 离线时仍可查看已保存配置的群。

业务配置保存在 PostgreSQL。第一次启动自动导入旧 `config.toml` 和环境变量，之后数据库优先，旧文件不会覆盖后台修改。密钥只显示是否已设置：留空保留，勾选清除才删除。配置按分组独立保存，类型校验或数据库保存失败不会改变运行配置；过期页面无法覆盖新修改。

先在 **AI 模型** 点击「添加模型」，填写名称、模型 ID 并选择账号；没有账号时可直接新建 OpenAI 兼容 API 或 Codex 订阅账号。模型以摘要卡片展示，点击「编辑」打开侧栏；共享账号和 Codex 登录态在「账号与凭据」管理。然后到 **AI 配置 → 功能与参数**，选择默认对话/视觉模型及各功能使用的模型。两页独立保存，顶部保存栏随滚动固定；切页或关闭页面时提醒未保存修改。多个模型可共用一个连接；模型分别声明聊天、读图、生图、编辑图片、工具调用和结构化输出能力。对话操作需要聊天与工具调用，图片理解需要聊天与读图，功能下拉框按所需能力过滤。各文本功能默认继承对话模型，图片理解默认继承视觉模型；生图和编辑图片需单独指定。选择“关闭此功能”后不会自动切换其他模型。保存立即生效，已开始的请求继续使用捕获的模型配置。

删除或停用被引用的模型、删除被模型引用的连接、撤销使用中的能力，需要先换绑或关闭相关功能；后端会拒绝悬空引用。旧配置首次启动迁移为连接和 Profile，保留对话与视觉选择。密钥只写入不回显，空白保留，明确勾选清除后才删除。每个模型可单独设置超时、推理强度和 API 输出预算。

能力直接勾选保存，无需测试解锁。保存后可选择执行能力诊断。测试会真实消耗对应账号额度；生图/编辑测试生成一张测试图片，结果在测试弹窗预览，不发到 QQ。成功表示该次请求通过，不能保证未来额度或权限。后台测试结果是当前页面的临时反馈，修改配置后清除，不冒充长期认证。

### Codex 订阅连接

Codex 模型可用性与账号和客户端版本有关；遇到模型拒绝错误时，应先核对服务端 CLI 版本和当前账号的模型列表。服务器需要代理时，在部署环境设置 `YUELING_CODEX_PROXY=http://host.docker.internal:7890`（替换成容器可达的代理地址），重新创建 Bot 容器后生效；它只传给 Codex 子进程，不改变其他服务的网络出口。Codex 后台文本能力测试最多等待45秒；生图和改图默认等待180秒，测试期间保持响应连接，避免代理等待超时。

Docker 镜像内置 Codex CLI 0.162.1（构建参数 `CODEX_VERSION` 可覆盖）；直接运行 Go 程序时需将同版本 Codex 安装到 PATH，或设置 `YUELING_CODEX_BINARY` 为可信可执行文件路径。每个连接使用 `data/codex/<连接ID>/auth.json`，目录0700、文件0600；登录态不保存在普通配置 JSON 中。

后台先保存 Codex 连接，在该连接下选择本机 `auth.json` 上传，或使用本机导入命令：

```bash
# 导入本机 Bot 的数据目录
 go run ./cmd/codex-auth -connection YOUR_CONNECTION_ID -data-dir ./data

# 通过 SSH 导入服务器实际挂载给 Bot 的数据目录（使用服务器绝对路径）
 go run ./cmd/codex-auth -connection YOUR_CONNECTION_ID -ssh user@server -data-dir /srv/yueling/data
```

默认从 `$CODEX_HOME/auth.json` 或 `~/.codex/auth.json` 读取；可用 `-source /path/to/auth.json` 指定，或 `-source -` 从标准输入读入。工具只接受可刷新的 ChatGPT 订阅登录态，拒绝 API Key 文件，不输出令牌。首次导入不会覆盖已有文件；重授权时先暂停该连接的请求，再显式使用 `-replace`。SSH 仅传输必要认证字段，不复制整个本机 Codex 目录。

若本机使用系统钥匙串而没有 auth.json，可以在独立目录完成文件模式登录后导入，或在服务器连接专属目录运行设备码登录：

```bash
CODEX_HOME=/srv/yueling/data/codex/YOUR_CONNECTION_ID codex -c 'cli_auth_credentials_store="file"' login --device-auth
```

登录要求和文件迁移方式见 [官方认证说明](https://learn.chatgpt.com/docs/auth)。服务器接管后续令牌刷新，不定时用本机旧文件覆盖。订阅额度与本机共享，失效或限额时返回错误，不自动改用付费 API。

Codex 适配器通过 app-server 请求文本、图片理解、业务工具调用和内置图片生成；每次模型请求使用临时会话和空工作目录，同一连接内请求排队。禁用 Shell、浏览器、外部连接、插件和子代理等执行能力，不加载本机工作区；业务工具调用先返回 Bot，再走已有权限、确认和防重复执行流程。该适配依赖 experimental dynamicTools 协议，升级 CLI 应先运行下述模拟协议检查。保留新版 CLI 执行工具调用所需的 code-mode host；生图请求单独启用内置图片工具并校验返回图片。Codex 不暴露 API 的最大输出 Token 控制，暂不支持结构化输出约束。

```bash
YUELING_TEST_CODEX=1 go test ./services/llm -run TestInstalledCodexWithFixtureProvider -v
```

该检查使用真实 Codex 程序和本地模拟推理端，不读取真实登录态或消耗订阅额度。实际账号是否能调用所填模型，需要在后台测试验证。

### 生成与编辑图片

给 OpenAI 兼容 API 连接建立生图/编辑配置，并在功能分配中分别选用。Bot 支持“画一张……”及“把这张图改成……”；编辑可以引用会话附件、引用消息图片或通过 QQ 号取得的头像。结果直接发送到当前群，不覆盖素材库。图片请求不自动重试，避免重复扣费；成功生成但发送失败时会明确说明。OpenAI 兼容 API 连接应支持 `/images/generations` 或 `/images/edits`，返回 base64 图片或可安全下载的公开图片 URL；Codex 订阅使用所选对话模型调用内置图片工具，无需额外 API Key。

也可以回复一条图片消息，`@月灵 照这张图生图，风格是水彩，保留人物和构图`。这种请求使用「编辑图片」配置，把引用的原图与风格描述一起发给模型；纯文字画图使用「生成图片」配置。参数和附件检查通过后，先给你的指令消息贴“处理中”表情，再下载原图、调用图片模型；表情回应失败不会中断生成。成功后引用你的指令发送图片。

头像也可以直接作为参考图，例如 `@月灵 用 @某人 的头像生图，改成水彩风格`、`@月灵 把我的头像画成动漫风格`，或直接指定 QQ 号。普通群成员即可使用，无需对方上传图片；多人指代不清时会先确认目标。头像识别使用视觉模型，参考头像生图使用「编辑图片」配置。

超级管理员可以回复图片说 `@月灵 把这张表情改名为开心`，机器人按附件内容定位本地素材，无需提供 hash 或旧名字；同图对应多个素材时先确认目标。匹配支持原图和程序保存、发送时的压缩结果，QQ 再次转码后无法精确匹配时会如实说明。后台「图片与打包 → 素材库」支持单张重命名，以及按文件修改时间或名称正序、倒序排列；默认最新修改在前，排序后再分页。重命名直接修改文件名，保留 hash、文件时间、类目和语录所属群，不复制图片或产生回收站副本。

后台「系统配置 → 机器人 → 黑名单」提供全局 QQ 黑名单，可填入其他机器人账号，多个号码用逗号或空格分隔。保存后立即忽略这些账号的群聊、私聊消息和戳一戳，包括 AI、主动插话与自动回复；清空或移除号码即可解除。群聊 AI 调用超限后静默忽略，避免限流提示继续触发其他机器人。

AI、限流、代理、管理员、命令前缀、插件开关等保存后立即应用。图片类目、表情包服务、时区、B站登录态和监听/连接设置标记为 **重启生效**：先保存，再退出并由 Docker `restart: unless-stopped` 或进程管理器重新启动。后台会区分已保存与待重启状态，需重启字段在当前进程中仍使用原值。直接运行二进制而未配置进程管理器时，需要手动重新启动。关闭后台会停止管理入口；修改监听端口时还需确保部署端口映射与访问地址匹配。

收到退出信号或重启请求后，服务停止新接入并等待 HTTP、QQ 消息和后台任务结束，再关闭数据库。退出等待最多 30 秒；部署时应给进程预留至少这一时长的停止宽限期。

B站轮询、关键词和回复策略在 **B站 → 监控与回复**，账号登录态在 **B站 → 账号配置**；群级插件策略、AI 提示词和订阅配置分别放在对应功能页，日报保留独立页面；全局插件关闭优先于群级开关，也暂停对应的订阅、日报、提醒和B站定时任务。已经开始的请求不会被强制撤销。

启动只需提供 `YUELING_DATABASE_DSN`（数据库口令可用 `PGPASSWORD`）和可选的 `YUELING_BOT_DATA_DIR`。也可把 [bootstrap.example.toml](bootstrap.example.toml) 复制为 `config.toml`。数据库连接地址不能从尚未连接的数据库读取，数据根目录用于定位挂载文件，因此这两项留在启动环境或最小 TOML。数据库首次为空时，还需用 `YUELING_WEBUI_PASSWORD` 提供初始后台密码；有配置记录后，从数据库恢复密码和业务设置。旧完整示例仅用于首次导入，配置接口不会写回 TOML/YAML。

**匹配方式说明**

- **精确** — 整条消息只含这个词才触发，不会误触
- **命令** — 消息开头匹配，后面可带参数
- **关键词** — 消息中包含此词即触发
- **正则** — 正则表达式匹配
- **被动** — 无需触发词，自动响应特定事件

## B站插件

后台菜单 **B站 → 监控与回复** 可设置监控开关、轮询间隔（1分钟 / 5分钟 / 自定义）、QQ 接收人、自动回复模式、关键词规则、AI 提示词、冷却/限额和视频查询默认值。保存后立即生效，按账号持久化，重启后仍保留；无需为这些设置修改配置文件。首次连接账号时在 **B站 → 账号配置** 保存登录 Cookie。旧配置文件与环境变量仅用于首次导入，已有数据库配置后不会覆盖后台保存值。读取私信需要 `DedeUserID`、`SESSDATA`；发送还需要 `bili_jct`、`buvid3`。接收 QQ 应能与机器人私聊。

首次启动只建立私信基线，不补发已有消息；之后默认每 1 分钟自动检查新私信，向配置的 QQ 转发联系人昵称、时间、内容和固定会话编号。监控开关与间隔可在后台修改，`B站检查` 只是可选的立即检查，不需要手动触发日常轮询。检查点、回复模式和关键词规则保存于 PostgreSQL，按登录账号隔离；重启后恢复。图片私信显示链接，其他类型显示摘要，撤回、系统通知和对方自动回复不触发自动回复。

| 指令 | 用途 | 使用范围 |
|------|------|----------|
| `B站视频 <BV号 / av号 / 视频链接> [分P序号]` | 当前在线、播放、点赞、投币、收藏、分享、弹幕和评论 | 群聊 / 私聊 |
| `B站最近视频 [UP主UID] [数量1-10]` | 按发布时间查询最近投稿，默认使用 `bilibili.uid`、`recent_count` | 群聊 / 私聊 |
| `B站状态` / `B站未读` / `B站检查` | 查看状态、未读计数或立即同步 | 接收人或超级管理员私聊 |
| `B站回复 <内容>` / `B站回复 <会话编号> <内容>` | 单联系人直接回复，多人使用通知中的固定编号 | 接收人或超级管理员私聊 |
| `B站会话` | 查看联系人昵称、固定编号和最近消息摘要 | 接收人或超级管理员私聊 |
| `B站自动回复 <关闭 / 关键词 / AI / 混合>` | 切换自动回复策略 | 接收人或超级管理员私聊 |
| `B站关键词` | 查看关键词规则 | 接收人或超级管理员私聊 |
| `B站添加关键词 <词> <回复>` | 新建或覆盖包含匹配规则 | 接收人或超级管理员私聊 |
| `B站删除关键词 <词>` | 删除规则 | 接收人或超级管理员私聊 |

自动回复**默认关闭**。关键词模式使用第一条命中规则；AI 模式使用后台选中的对话 Profile，仅根据当前文本私信生成回复；混合模式优先关键词、未命中才用 AI。仅文本私信参与自动回复，默认同一人冷却 60 秒、全账号每分钟最多 5 次；限额内以外的消息仍转发 QQ。关键词初始值来自 `[[bilibili.keywords]]`，后续后台或 QQ 指令修改的规则与模式使用同一份持久化数据，并优先于配置文件。后台保存不会清除游标和转发进度。会话编号按新私信首次转发分配，重启后不变；历史基线不作为直接回复目标，多人且未指定编号时会提示选择，不猜测目标。

视频在线人数按选中的分 P 查询；最近投稿默认查询 P1，播放与互动数据为整稿统计。在线接口不可用时保留其余统计。使用完整 bilibili.com 视频链接，暂不展开 b23 短链接；链接中的 `p=` 不代替显式分P参数。

私信发送失败或超时会反馈 QQ，自动回复的发送尝试在请求前持久化，结果不确定时不自动重发，需核对 B站后人工处理。QQ 转发采用成功后记录的重试方式，极端情况下（消息已送达但连接超时/进程在记录前退出）可能重复通知。不会标记读取的 B站私信为已读；B站发送接口自身会将会话标为已读。

视频、未读计数、会话列表、私信记录和发送均使用 [bpi-go](https://github.com/Yuelioi/bpi-go)，依赖锁定本批私信 API 的提交。会话分“用户/系统”和“未关注”两类分页后合并去重，规避“全部会话”查询忽略翻页游标的限制。

SDK 提交尚未推送时，本地联合开发可在仓库根执行 `go work init . ../../tools/bpi-go`（两个仓库需按该相对路径放置）。工作区文件只用于本地联调，不提交；独立构建和其他机器下载依赖需先让该 SDK 提交可从远端访问。

## 加群审核

> 群内命令需要 **管理员 / 群主** 权限，后台登录后可管理全局和单群配置。

后台「入群审核」支持全局默认名单，以及单群「继承全局 / 独立配置 / 全部留人工」。独立配置完整覆盖全局黑白名单（空名单也不会回退到全局）；已有群名单自动保留为独立配置，未配置的群默认继承全局。切换为留人工会保留名单。保存后立即生效，无需重启；机器人需在线、有群管理权限，且本群加群审核插件已启用。

页面可输入申请理由预览审核结果。每份名单最多 200 个词，每词最多 128 字，支持换行或中英文逗号分隔。

加群申请的**验证理由**命中关键词时自动处理：命中拒绝词→拒绝，命中通过词→通过，**拒绝优先**，都不命中则留管理员人工处理。

## AI 对话

| 触发方式 | 匹配 | 说明 |
|---------|------|------|
| `@月灵 <内容>` | 被动 | 触发 AI 对话 |
| `月灵 <内容>`（消息开头） | 关键词 | 触发 AI 对话 |

对话自动续接上下文，并支持从持久检查点恢复（见下方“对话理解与恢复”）。翻译、改写、摘要、代码解释等纯文本任务由 AI 直接回答；只有真实外部动作才调用 Tool。Tool 包括天气、搜索、航班/火车、计算、汇率、自然语言提醒、待办、群聊统计、个人资料与记忆、订阅、知识库及受权限控制的群管理等。群插件在 WebUI 中被禁用时，对应 AI Tool 也会同步禁用。

个人待办列表返回稳定的条目 ID；完成或删除使用该 ID，列表增删不会改变其他条目的编号。每人最多保留 20 条未完成待办，数据库在事务中检查配额和用户归属。

### 对话理解与恢复

工具选择保留关键词快速匹配，用于预加载本轮参数定义；模型接口始终使用固定顺序的“发现能力 / 执行已加载能力”两个工具入口。能力目录保持稳定，具体参数可按自然表达查询；目录不是授权，执行时仍检查当前用户权限、群插件开关、业务参数和必要的确认。

普通 AI 对话每个群共享一份上下文，不同群互相隔离；每轮保留发言者身份，群友可接续之前与 AI 的对话。私聊仍按用户隔离，活跃会话保留30分钟；PostgreSQL 保存最近对话、附件引用、工具结果及历史摘要，可恢复最后24小时内的检查点，包括服务重启后。超过8轮或历史长度预算时，较早完整轮次压缩为事实摘要，并保留最近约4轮、12000字符预算内的完整轮次，为后续追加留出余量；近期工具协议保留。摘要生成失败会注明缺失，不把猜测当记忆。附件原始链接失效时仍需重新附图。普通图片交流不会主动询问是否添加语录；只有明确要求保存时才补问缺少的必要信息。

「重新开始」等原有重置入口同时清除当前群共享的持久会话；未完成的危险操作确认不会跨重启恢复。检查点在每轮结束时保存，不提供外部动作与数据库之间的跨系统事务保证。日常回复长度作为简短目标，用户要求详细解释时允许展开。

模型输入按固定运行规则、稳定能力目录、本群设定与群规则、历史摘要、近期完整对话、本轮资料与问题排列。当前时间、发言者身份、关系与个人记忆随本轮输入保存，不再每轮改写历史前缀；旧轮资料不代表新授权。群设定修改或历史压缩会重新建立前缀缓存，24小时检查点期限不代表模型服务端缓存期限。

**AI → 缓存与用量** 默认展示全部范围，可按群及1/7/30/90天筛选。统计成功返回的模型请求（含工具续轮、历史压缩、记忆提取和后台任务；能力测试也计入，未关联群的请求归入“私聊 / 后台任务”），按群、功能、配置 ID 和实际模型汇总请求、输入/输出 tokens、缓存命中/未命中及响应耗时；不包含独立定时任务或失败HTTP请求。数据按日持久化，不保存提示词或回复正文。兼容 DeepSeek 的 `prompt_cache_hit_tokens` 和通用 `prompt_tokens_details.cached_tokens`；未返回缓存字段显示“未提供”，不按零命中处理。命中率以已报告缓存数据的输入 tokens 为分母加权，同时显示报告覆盖率；不推算服务商账单。鉴权查询接口为 `GET /api/webui/ai/model-usage?days=7`，可追加 `group_id`，省略则返回全部，`group_id=0` 为私聊汇总。

开发者可运行 `go run ./cmd/ai-eval -config config.toml`，对比关键词路由与工具发现；使用 `-models 模型A,模型B` 比较同一服务上的模型。只使用虚构对话和模拟业务工具，不连接QQ，输出每个案例的执行结果、耗时和token。实测与范围见 [AI质量评测](docs/ai-quality-evaluation.md)。

| `提取群聊待办，关注发布计划` | 整理行动项、已明确的负责人和时间，不自动创建任务 |
| `列出群聊未解决问题` | 从聊天资料提取尚未解决的问题 |
| 总结后问 `昨天呢`、`只列待办` | 延续当前总结任务，按新范围或新类型重新读取资料 |

总结后可以继续说 `详细解释一下`、`展开说说`，再切换日期。开始新主题、引用其他消息或发送附件后，不再默认延续上次总结任务。

普通总结会使用群昵称回顾具体说法、建议和接话，不输出账号、来源编号或空的会议纪要栏目。只有明确要求待办、结论或未解决问题时，才按相应方式整理；没有昵称时使用群友称呼，只有链接的内容不会被猜测。

这些请求受群聊日报插件开关控制。最近记录最多 100 条；今日、昨日、本周、近 7 天使用本群本地已保存记录，按时间顺序取前若干条，不能视为完整时间段的全部结论。内容过长时会截断资料并提示取样范围。提示模型仅按已有资料回答，资料不足时说明限制。

AI 对话将模型请求、工具执行和最终回复分别处理：仅对服务限流和暂时性服务故障有限重试，不重放已执行动作；异常工具标记、截断调用和不符合参数定义的调用不会直接执行或作为最终回复发送。接口认证、兼容性、限流和超时会显示不同提示。失败发生在工具执行后时，会提醒先核对结果，避免重复操作。

| 说法 | 作用 |
|------|------|
| `月灵 新对话` | 清空本群共享的短期上下文，同时取消尚未完成的本会话请求 |

群管理员可以把公开信息源接入群聊。月灵每 10 分钟检查一次更新，支持 RSS 2.0、Atom 与 RSS 1.0，也可以订阅 GitHub Releases 的 `.atom` 地址或 RSSHub 生成的公开路由。

| 命令 | 作用 |
|------|------|
| `订阅添加 <URL> [名称]` | 添加信息源；以当前最新内容为基线，不补发历史文章 |
| `订阅B站视频 <UID/主页> [名称]` | 订阅 UP 主的新投稿 |
| `订阅B站动态 <UID/主页> [名称]` | 订阅 UP 主动态 |
| `订阅B站直播 <房间号/链接> [名称]` | 订阅直播间开播 |
| `订阅X <用户名/主页> [名称]` | 订阅 X 用户发推 |
| `订阅小红书 <用户ID/主页> [名称]` | 订阅用户笔记；使用完整主页链接中的 24 位 ID |
| `订阅GitHub <owner/repo或仓库链接> [名称]` | 订阅 GitHub 版本发布 |
| `订阅GitHubIssues <owner/repo或仓库链接> [名称]` | 订阅 GitHub Issues（所有状态） |
| `订阅列表` | 查看本群全部订阅及 ID |
| `订阅状态` | 查看异常源、待推送条数和静默设置 |
| `订阅暂停 <ID>` | 暂停单个源并清理它尚未发送的内容 |
| `订阅恢复 <ID>` | 恢复单个源，并在下一轮重新检查 |
| `订阅静默 23:00-08:00` | 夜间继续抓取，静默结束后合并推送 |
| `订阅静默 off` | 关闭静默时段 |
| `订阅检查` | 立即检查；非静默时段同步推送新内容 |
| `订阅删除 <ID>` | 删除指定订阅 |

平台快捷订阅由 `[feed].rsshub_base` 指向的 RSSHub 实例提供。公共演示实例可能限流、触发 Cloudflare 验证或受网络影响；本仓库的 Docker Compose 会自动启动带 Chromium 的自建 RSSHub，并让 Bot 使用 `http://rsshub:1200`。非 Docker 部署可设置 `[tools].proxy`，或自行部署 RSSHub 后修改 `rsshub_base`。B站投稿路由存在反爬风险，动态路由通常更稳定。

如果要把 RSSHub 手工合并进旧版或自行维护的 Compose 文件，必须同时加入四部分：`rsshub` 与 `rsshub-redis` 服务、Bot 的 `YUELING_FEED_RSSHUB_BASE=http://rsshub:1200` 环境变量、Bot 对 `rsshub` 的健康依赖，以及顶层 `volumes` 中的 `rsshub-redis-data:` 声明。合并后先执行 `docker compose config --quiet`；该命令通过后再执行 `pull` 或 `up`。

RSSHub 的可选账号凭证统一放在项目根目录 `.env.rsshub`（参考 `.env.rsshub.example`）。X 用户时间线推荐只配置登录 `x.com` 后 Cookie 中的 `TWITTER_AUTH_TOKEN`；也可改用 X Developer App 的 `TWITTER_CONSUMER_KEY` + `TWITTER_CONSUMER_SECRET`，两种方式二选一。B站动态默认由内置 Chromium 获取访客 Cookie；如果仍遇到源站 `-352` 风控，可在 `.env.rsshub` 添加 `BILIBILI_COOKIE_<登录账号UID>`，其值必须是浏览器请求中的完整 Cookie。

小红书笔记通过 RSSHub 获取，需要 Chromium（仓库 Compose 已包含），可在 `.env.rsshub` 配置 `XIAOHONGSHU_COOKIE`。不支持 `xhslink.com` 短链，请使用完整用户主页链接。GitHub 版本发布使用官方 `releases.atom`；Issues 使用 RSSHub，可配置 `GITHUB_ACCESS_TOKEN` 提高 API 配额。后台入口为「订阅中心 → 平台快捷订阅」。

RSSHub 已锁定基础镜像版本并应用小红书修补，不自动跟随上游更新。首次部署执行 `docker compose build rsshub`。原因、验证结果及后续升级方式见 [RSSHub 小红书修补说明](deploy/rsshub/README.md)。

大陆网络中，RSSHub 容器访问 X 通常还需要独立代理。可在 `.env.rsshub` 设置 `PROXY_URI=http://host.docker.internal:7890`，并按 `.env.rsshub.example` 的 `PROXY_URL_REGEX` 只代理 X 相关域名，让 B站继续直连。

每群最多 10 个订阅，默认每 5 分钟检查，后台「订阅中心 → 推送策略」可按群设置 5–1440 分钟，保存后生效。后台「检查并推送全部订阅」立即检查所有群启用的订阅，不受下次检查时间限制；暂停订阅不抓取，静默群继续入队。群内 `订阅检查` 仍只检查本群。同一轮相同 URL 只抓取一次，各群独立记录更新进度，并合并本群的待推送内容。每个源单轮最多接收 5 条新内容。新条目和订阅游标会先在同一事务中写入 PostgreSQL 持久队列，再按群合并推送；QQ 发送失败、Bot 重启或处于静默期都不会丢更新。每条群消息最多合并 12 条，剩余内容留到下一轮。连续抓取失败会按 10、20、40 分钟逐级退避，最长 6 小时，成功后自动恢复正常频率，错误和下次检查时间可在 `订阅状态` 或 WebUI 查看。

后台「检测当前列表（不推送）」可检测全部或筛选群的订阅，也可逐条检测，包含暂停订阅。检测不发送消息、不推进游标、不修改推送队列或调度；结果显示检测时间，并区分疑似认证失败、缺少配置、403 拒绝访问、429 限流、超时和其他故障。检测结果仅保留在当前页面，刷新后可重新检测；定时拉取的最近错误仍保存在订阅记录中。RSSHub 可能返回缓存，因此“可读取”不是上游 token 未过期的保证；平台凭证需在 RSSHub 部署环境更新。

普通订阅抓取仅允许公网 HTTP/HTTPS 地址，限制响应体大小，并会拒绝回环、私网、链路本地和云元数据地址；只有配置文件明确指定的 RSSHub 同源地址可访问内网。插件禁用期间只同步游标并清空待推送队列，恢复后不会刷屏补发。

### 群知识库问答

每个群拥有完全独立的资料库。管理员可以录入长期有效的文字资料，或从公网 HTML/纯文本网页导入正文；群员只有显式提问时才会触发 AI，不会在后台持续消耗调用量。

| 命令 | 作用 |
|------|------|
| `知识添加 [标题] \| <内容>` | 添加一条文本知识（群管理员） |
| 回复文字 + `知识添加 [标题]` | 把被回复内容保存到知识库（群管理员） |
| `知识导入 <URL> [标题]` | 安全抓取公网网页正文（群管理员） |
| `知识列表` | 查看本群专属及共享知识的 ID、标题和作用域 |
| `知识问 <问题>` | 检索本群专属资料和所有群共享资料，并用资料标题注明回答依据 |
| `知识删除 <ID>` | 删除指定知识（群管理员） |

知识条目还可以在 WebUI 或通过管理员自然语言设置最多 10 个“快捷触发词”。例如给下载地址知识设置 `ae下载` 后，群友只需发送完全相同的文字，Bot 就会立即回复该条内容或来源链接：不需要 `@月灵`。WebUI 可选择“所有群共享”或某个具体群；检索会合并共享知识与本群知识，同名快捷词由本群专属条目优先。

每个群专属空间和共享空间各最多 100 条，单条最多 12,000 字。网页导入沿用公网 URL 与响应体限制；检索结果会作为不可信参考资料交给模型，回答被要求只依据当前群可用的命中知识，不足时明确说明，不会检索其他群的专属资料，也不会把网页里的提示词当成指令。

AI 也可以调用当前 NapCat 连接上的 QQ 动作：

| 示例 | 效果 |
|------|------|
| 回复一条消息并发送 `@月灵 把这条设精` | 将被引用消息设为精华 |
| `@月灵 把我的群名片改成 今天不加班` | 修改自己的群名片 |
| `@月灵 给我一个 摸鱼冠军 的头衔` | 设置自己的专属头衔 |
| `@月灵 戳一下 @某人` | 戳一戳被提及成员 |
| `@月灵 撤回刚才那条广告` | 查询近期消息并按真实消息 ID 撤回 |
| `@月灵 禁言刚才说脏话的人十分钟` | 查询近期消息并按真实用户 ID 禁言 |

`get_chat_history` 会为每条记录提供消息 ID 和用户 ID，供撤回、禁言等 QQ 动作继续调用。所有群友都可以使用 AI 撤回和禁言工具；普通成员只能修改自己的群名片和头衔，群管理员、群主及超级管理员可以修改本消息中额外 `@` 的第一个成员。实际动作仍要求 Bot 账号在群内拥有相应 QQ 权限。

AI 网页读取只接收公开 HTTP/HTTPS 地址，并限制响应体积；本地、私网和含账号密码的网页地址会被拒绝。

## 联网搜索与自然解读

先到后台「AI 模型」点击「添加搜索配置」，选择支持 DeepSeek Search/Fetch 的 API 账号并保存；纯搜索配置无需推理模型 ID。然后到「AI 配置」把「联网搜索与网页阅读」单独指定为这份配置。未指定或关闭时不会继承聊天模型，聊天使用 Codex 也不影响搜索配置。

只有明确要求搜索、查证、找资料，或问题需要最新、近期、实时信息时才联网。普通闲聊、稳定概念的“是什么/为什么”、翻译和改写尽量直接回答；明确要求“不搜索”时不会调用搜索。Tavily 不再参与请求，旧 tavily_key 仅为兼容旧配置保留读取。

| 请求示例 | 行为 |
| --- | --- |
| `@月灵 帮我搜一下 DeepSeek 最新功能` | 搜索摘要与来源，必要时读原文 |
| `@月灵 量子纠缠是什么` | 直接解释，不自动联网 |
| 回复图片问 `@月灵 这是什么，解释一下` | 使用所选读图模型理解图片，回到共享对话回答 |
| `@月灵 总结这个链接，重点解释结论 https://example.com/article` | 读取指定网页，按重点解读；不自动扩展搜索 |
| `@月灵 不要搜索，翻译这段话` | 仅处理提供的内容 |

独立 zssm 命令与模型功能分配已移除。Search/Fetch 通过 DeepSeek 独立接口调用，使用搜索配置的账号；不会额外调用一次聊天模型。搜索默认5条，上限10条，关键词最长128个 Unicode 字符；搜索失败、余额不足与无结果分别反馈，不把错误当作没搜到。网页与图片资料不作为操作指令，回答需要出处时保留实际使用的来源链接。搜索与网页读取按请求另计费，后台能力测试需主动点击，测试不会自动启用搜索。

## 配置文件 `config.toml`

配置文件使用严格 TOML 解码：未知字段、错误类型会阻止启动，不再静默忽略或自动转换。升级前请按 `bootstrap.example.toml` 或 `config.example.toml` 核对字段。环境变量仍使用 `YUELING_` 前缀和下划线分隔；标量保持原有格式，数组使用 JSON，例如 `YUELING_BOT_SUPERUSERS='[123,456]'`、`YUELING_PLUGINS_DISABLED='[1,2]'`，模型档案数组同样使用 JSON。空环境变量不覆盖文件值；使用 `[]` 明确清空数组。解析错误不会打印配置内容或凭据。


### 图片类目配置表 `[[image.entry]]`

随机图片 / 4合1 / 外链 三类图片命令由配置表驱动。**不配则用内置默认表**（龙图/福瑞/老公/老婆/沙雕图/杂鱼/美少女/ba + 吃喝玩乐 4合1 + 随机猫猫）；**一旦填写则整体覆盖**默认表。加一个类目只改配置，帮助与命令自动跟随。

每条 entry 两个维度正交：`kind` 管**调用方式**，`arg` 管**添加规则**。

`kind`（调用方式）：

| kind | 调用 | 必填字段 |
|------|------|---------|
| `single`（默认，可省） | 随机发一张 | `folder` `call` |
| `grid` | 挑 4 张拼 2×2 网格、按名字列菜单 | `folder` `call` `add`（且 arg=true） |
| `external` | 发外链 URL | `call` `url` |

`arg`（添加规则，**看这一项就知道怎么加**）：

| arg | 添加方式 | 文件名 |
|------|---------|--------|
| `false`（single 默认） | `添加X` + 图片，直接加 | 图片 hash |
| `true`（grid 默认/强制） | `添加X <名字>` + 图片，名字必填 | `名字_hash`（4合1 用名字当标签） |

> 省略 `arg` 时按 kind 取默认（grid→true、single→false）；`grid` 不能 `arg=false`。`single` 也能配 `arg=true` 做「带名字标签的随机图」。
> `external` 可选 `pick`：接口返回 JSON 时按路径取图，留空则把 `url` 的响应本身当图片。语法：`a.b` 取字段、`[N]` 取第 N 个、`[*]`/`[random]` 随机一个（**数组必须写下标**，如 `data[*].url`）。

```toml
# single：随机发一张，直接加图
[[image.entry]]
folder = "龙图"
call   = ["龙图", "龙图攻击"]
add    = "添加龙图"
arg    = false

# grid：4合1 网格，添加须带名字（如「添加吃的 麻辣烫」）
[[image.entry]]
folder = "吃的"
call   = ["随机吃的", "吃啥", "吃什么", "来点吃的"]
add    = "添加吃的"
kind   = "grid"
arg    = true

# external：外链，响应直接是图
[[image.entry]]
call = ["随机猫猫", "来点猫猫"]
kind = "external"
url  = "http://edgecats.net/"

# external：接口返回 JSON，从 data.url 取图（data 是对象）
[[image.entry]]
call = ["来只狗", "随机狗"]
kind = "external"
url  = "https://api.example.com/dog"
pick = "data.url"

# external：列表 + 相对路径——[*] 随机取项，base 补全站点前缀
[[image.entry]]
call = ["随机插画", "来点插画"]
kind = "external"
url  = "https://pln.yuelili.com/api/v1/artworks/random?limit=24"
pick = "data[*].url"               # data 列表随机一项 → .url 得 /api/v1/files/xxx.png
base = "https://pln.yuelili.com"   # 补成完整地址再发
```

> `external` 可选 `base`：`pick` 取到相对路径（`/...`）时拼站点前缀；取到的已是完整 `http(s)` 地址则忽略。

> 语录、表情因检索逻辑特殊（群隔离白名单 / 关键词空格触发），是独立插件，不在此配置表中。

## WebUI 管理后台

启用 `[webui]` 后，Bot 进程会同时启动一个密码保护的管理后台。后台包含运行总览、每群插件策略、全局/按群命令调用统计、聊天词云与群友常用语、AI 默认与群级对话风格、群消息发送、群聊日报调度、RSS/Atom 订阅、群知识库、AI 好感度和长期记忆管理。运行期管理数据统一写入 PostgreSQL，不会写回 `config.toml`。

| 页面 | 用途 |
|------|------|
| 运行总览 | 查看 Bot 连接、群聊、插件、日报、订阅和 AI 数据概况 |
| 插件 | 全局插件开关与群级策略，也可批量应用到所有群 |
| 调用统计 | 查看所有群汇总或单群最近 7/30/90 天命令趋势、独立用户和常用命令排行 |
| 消息中心 | 组合文字、艾特和图片并发送到指定群 |
| AI | 连接账号、模型能力、功能分配、Codex 登录态导入与能力测试，配置限流/上下文并查看缓存用量 |
| 群聊日报 | 可视化设置每天的发送时间和消息采样数量 |
| 订阅 | 按群管理信息源、静默时段、队列和源健康状态；配置 RSSHub 服务 |
| 群知识库 | 分别管理所有群共享知识与群专属知识，录入文本或导入网页 |
| 关系引擎 | 查询及调整群成员的 AI 好感度 |
| 长期记忆 | 检索、删除或按用户清空 AI 自动提取的偏好 |
| B站 | 配置账号、私信监控、QQ 通知与自动回复 |
| 图片与打包 | 配置图片转换、素材目录/命令和打包限制 |
| 工具与服务 | 配置天气、搜索、代理和表情包服务 |
| 连接配置 | 配置 QQ WebSocket 和消息接口 |
| 系统配置 | 配置机器人、后台、数据库连接池，查看启动信息 |

WebUI 不需要单独设置 token，登录只看 `[webui].password`。连续输错密码会被短暂限流；如果页面提示“请先登录”，打开 `/login` 或重新登录即可。如果提示“密码错误”，使用后台保存的管理密码；首次初始化使用启动环境中的 `YUELING_WEBUI_PASSWORD`。

NapCat 的 token 是另一套鉴权，只影响 Bot 和 NapCat 的 WebSocket 连接：`[napcat].token` 必须和 NapCat 网络配置里的 access token 一致。建议始终设置强 token；反向 WS 留空时不会做身份校验，但只接受回环或私网来源，并拒绝跨站浏览器连接。

```bash
export YUELING_TEST_DATABASE_DSN='postgres://user:password@127.0.0.1:5432/yueling_test?sslmode=disable'
go test ./...
```

### Docker

```bash
cp config.example.toml config.toml   # 填写配置
task docker:up                       # 校验配置，构建并启动完整服务栈
```

`docker-compose.yml` 默认使用 `ghcr.io/yuelioi/yueling-go:latest`，服务器可执行 `docker compose pull && docker compose up -d` 直接更新；执行带 `--build` 的 `task docker:up` 时则会从当前源码构建。Compose 会启动 Bot、PostgreSQL、NapCat、meme-generator-rs、RSSHub 及其 Redis 缓存。Dockerfile 内会执行前端构建并把 `webui/dist` 打进运行镜像。结构化数据全部进入 Compose 内的 PostgreSQL；数据库直接使用带 `zhparser` 的 `zhparser/zhparser:alpine-16` 镜像，无需在本机编译 PostgreSQL。该上游镜像仅发布 `linux/amd64`，Compose 已固定平台，ARM 版 Docker Desktop 会自动通过模拟运行。聊天中文全文索引和词云分词都在 PG 内完成，PG 默认不向宿主机暴露端口。启用 `[webui]` 后，可通过 `http://127.0.0.1:9080` 访问。

生产部署请在项目目录的 `.env` 设置数据库密码：

```dotenv
POSTGRES_PASSWORD=请替换为强密码
```

Compose 会通过 `PGPASSWORD` 把密码单独传给 PostgreSQL 驱动，不会把密码拼进连接 URL，因此密码可以包含 `@`、`:`、`/` 等 URL 保留字符。

meme-generator-rs 服务**默认随 bot 一起启动**。启动后在 `config.toml` 中设置：

```toml
[tools]
meme_server = "http://meme:2233"   # Docker 内服务名固定为 meme
```

不需要表情包生成时，可单独只启动 bot：

```bash
task docker:bot
```

### AI 兼容性检查

`go run ./cmd/ai-check -config config.toml` 使用当前 AI 配置发送少量虚构测试消息，验证实际总结工具定义、结构化结果、多轮推理回传和无工具的纯文本总结。会消耗少量模型额度，但不连接 QQ、不读取群聊、不访问数据库，也不输出密钥或聊天正文。支持 `YUELING_AI_*` 环境变量覆盖配置。

只检查群总结时，可运行 `go run ./cmd/ai-check -config config.toml -summary-only -summary-records 50`，它与实际总结使用同一请求构建器和回复长度要求。默认使用50条虚构资料，可设置2—100条。诊断“取到记录但没有正文”时，查看同一消息的 `model_text` / `summary` 日志：`detail` 区分额度耗尽、只有推理、空正文和协议标记，后面的数字记录结束原因、输出额度、已用 token 和正文/推理长度，不记录内容。

主动插话优先接最新一句，最近两句用于理解指代，其余只作为背景；只保留五分钟内最多八条消息。新消息到来时取消过时生成，无法接话时保持安静。三分钟发送冷却与每天五次上限保留，生成取消或静默不占用发送次数。

`go run ./cmd/ai-check -proactive-style -model deepseek-flash` 使用虚构聊天检查话题切换、最近指代和信息不足时的静默；不会向QQ群发送消息。

`go run ./cmd/ai-check -summary-style -model deepseek-flash` 检查四组虚构聊天的具体事实、昵称和内部编号隔离，同时输出虚构总结供人工检查口吻。`-model` 仅覆盖这次诊断的模型，不更改运行配置。该检查会调用配置中的模型服务，不代表所有真实群聊的质量评分。

对话、日报、知识库、记忆、主动聊天、图文解释和订阅翻译共用模型请求模块。已知 DeepSeek V4 / deepseek-flash 的通用对话默认使用 `low`，纯文本整理默认使用 `none`；可通过 `ai.reasoning_effort` 显式覆盖。其他模型保留原策略。群总结按 `ai.reply_max_chars` 给出400—900字的目标上限，内容少时更短；日常短回复偏好不会把总结强行压成话题标签。`ai.max_tokens` 仍是生成预算，包含启用时的内部推理。纯文本整理的额度耗尽后不再用相同预算重复生成。历史推理仅保存在短期模型会话中用于协议回传，不作为群聊正文发送。

产品对照、架构取舍及剩余范围见 [AI 架构实测与实现](docs/ai-evaluation.md)，当前测试结果和复现命令见 [月灵验证记录](docs/ai-evaluation-yueling.md)。

### 构建环境升级

源码构建要求 Go 1.27.2；WebUI 和 CI 使用 Node 24 LTS、pnpm 11.1.2。Docker 构建阶段使用同一版本系列，运行阶段使用 Alpine 3.23。本次升级不改变 PostgreSQL 表结构，不要求清空数据或数据库大版本升级。回退时使用原源码及对应锁文件/工具链，不要单独降级 `go.mod` 或前端依赖。

配置解析已从 Viper 切换到直接 TOML 解码，旧的未知字段和非 JSON 数组环境变量需要按上节调整。Go 接口也有破坏性变更：AI 限流通过 `Engine.AllowAICall` 调用；知识库通过注入的 `knowledge.Manager` / `db.KnowledgeStore` 使用；在线配置用 `runtimeconfig.NewPostgresStore(database)`；图片任务 `imaging.Run` 和网页导入接受当前任务的 context。仓库内调用方已迁移，外部插件需同步修改。


### 模块装配与接口迁移

应用入口 `internal/app` 负责打开数据库、构造业务模块、注册处理器和有序关闭资源。生产代码不再提供全局 `db.DB` 或 `db.Init`；`db.Open(config)` 返回由调用方管理生命周期的数据库连接。Store 在构造时保存该连接，替换其他模块的连接不会影响已构造实例。

| 原入口/行为 | 升级后 |
| --- | --- |
| 全局 `db.*` 业务查询 | `NewChatStore`、`NewAffinityStore`、`NewGroupStore`、`NewGameStore`、`NewCommandUsageStore`、`NewProfileStore` 等显式实例 |
| AI 全局注册、会话、模型测试客户端 | `ai.NewEngine(ai.EngineDependencies{...})`，模型后端可通过 `ModelBackend` 注入 |
| 记忆函数和删除代次全局共享 | `ai.MemoryManager`；AI、QQ 群规则与 WebUI 使用同一个实例 |
| `tools.RegisterAll` 的位置参数 | `tools.RegisterAll(engine.Registry, tools.Dependencies{...})` |
| WebUI 创建后逐项绑定业务模块 | `webui.New(config, webui.Dependencies{...})`；`BindBot` 仅订阅连接变化 |
| B 站依赖隐式全局数据库 | `bilibili.NewPostgresStore(database)` 注入 CheckpointStore |

事务现在维护业务约束：待办并发新增不超过 20 条、记忆去重/淘汰/新增一起提交、群规则不超过 10 条、同用户同群同日签到只奖励一次、入群名单并发去重、好感度档位整组替换。显式记忆不会被自动提取覆盖；清除或删除后，在途的旧记忆提取结果会失效。待办完成和删除使用列表返回的稳定 ID，并校验用户归属。

这些接口变更不改表结构。外部插件需要按新的构造函数注入依赖；不能继续引用已经删除的全局入口。运行配置仍通过 `config.Current()` 读取当前进程的完整快照；限额等本地资源策略以及静态客户端属于进程级设施，不承担用户会话或业务数据库归属。

### AI 图片理解与语录上传

在群里 @机器人（或以机器人名字开头），可以直接带图或引用一条带图消息说：

- “帮我把这张图片上传到语录，名字叫小明。”
- “把第二张图存到语录，名字是今日名场面。”
- “帮我存到语录。” → AI 追问名字后，再 @机器人说“名字叫小明”。
- “这张截图写了什么？” → 使用配置的视觉模型识别画面和文字。

AI 使用统一素材工具读取生效的 `image.entry` 配置（空配置使用默认类目），支持类目名、调用别名和添加命令别名。表情关键词和语录名字必填，其余类目按配置的 `arg` / `kind` 规则；未配置添加入口的类目和外站不可上传。仅缺少必填信息、图片或选图有歧义时追问，不将表情请求存进语录。语录按当前群保存，遵守“上传素材”插件开关。单次最多8张、每张16MiB及1600万像素，逐张反馈成功、重复和失败。同一图片可用不同名字保存，也可以分别保存到不同群。旧 `/添加语录` 命令与 AI 共用校验、转换和原子存储。

直接保存、按序号选图不需要视觉模型；理解画面或识别文字需要配置支持图片输入的视觉模型（AI 的 VL 配置/视觉模型档案）。视觉识别有误差，单轮最多调用两次识别工具；无法确定时应请用户按序号选择。模型只能操作会话里已有图片编号，不能自行提交下载地址或本地路径。当前/引用消息的新图片会替换旧图片；会话过期或重置后需要重新附图。图片文字只作资料，不能授权上传操作。

### 后台图片素材库

登录管理后台，进入 **图片与打包 → 素材库**，可按类目浏览缩略图、放大预览、搜索名称和翻页；支持单张删除与多选删除，无需在群里输入命令或复制素材编号。原有转换、类目和打包配置保留在“图片与打包配置”页签。

素材库遵循生效的 `image.entry`：本地 single/grid 类目可管理，语录和表情单独保留；非空配置整体替换默认类目。external 网站类目只标明来源，不从网站拉图，也不能删除；即使配置了 folder 也不会视为本地素材。

所有列表、预览与删除接口均要求后台管理员登录，预览不开放公共图片地址。删除将文件移动到 `<data_dir>/trash/images/<类目>/<随机目录>/<原文件名>`，保留服务器手动恢复的副本。切换类目会清除选中项，多选删除按实际结果显示成功和失败数量，不会把失败显示为全部成功。

此前新增的图片列表、删除图片/语录/表情聊天命令及 AI 素材删除工具已移除。AI 图片理解和语录上传仍保留；撤回群消息不影响素材库文件。

### AI 本地图片删除

机器人超级管理员可在群内明确要求删除图片、表情或语录。AI 先查询配置内的本地素材，取得精确编号后才能删除；有多个候选时需明确选择，不能猜附件对应哪个文件。删除将文件移入回收站，不再参与随机取图；不删除外站内容。表情和普通图片库是全局共享的，因此普通群成员和仅有群管理员身份的用户不能通过 AI 删除。后台素材库的浏览与删除入口仍可使用。

明确 @机器人或以机器人名字开头的消息优先由 AI 独占处理，不再继续触发普通命令、图片插件、复读或主动回复；无 AI 触发的消息仍走原插件。聊天记录采集保留在分发前段，不产生额外回复。

超级管理员可让 AI 将已存本地素材转移类目或重命名，例如“把语录里的这张转成表情，名字叫开心”“把表情开心改名为高兴”。AI 先查询精确素材，多个候选会要求选择；目标类目要求名称时必须提供。转移先保存目标再回收原图，重命名保留类目与语录原群归属。随机图重命名不改变随机调用方式，外站素材不可操作。
