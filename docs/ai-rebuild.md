# AI 重构验收记录

状态：本文记录同类产品对照之前的模型层修复及其验证，未部署。后续架构改动、候选实测及当前代码验证见 [对照总报告](ai-evaluation.md) 与 [月灵验证报告](ai-evaluation-yueling.md)。本文的数据库通过记录不能代替后续代码复测。此前“已完成核心重构”的说法不成立；初版只有对话循环局部修复。

## 实现范围

- `services/llm` 统一对话、日报、知识库、记忆、主动聊天、图文解释、订阅翻译的模型请求。请求整体限时；仅临时 HTTP 错误有限重试；错误返回分类结果，不暴露提供商原始正文或密钥。
- `ai/conversation.go` 管理协议完整性与工具循环。保留历史推理和调用/结果配对，按完整轮次裁剪历史；异常输出最多纠正一次；最后一步只允许整理结果。
- `ai/dispatcher.go` 保留权限和群插件开关，执行前校验参数类型/必填/枚举，同轮相同参数复用结果，不重复执行。工具 panic 不破坏会话；失败后不自动重放不确定的动作。
- 会话锁等待可取消。工具上下文将取消传给 QQ 请求和主要 HTTP 工具。定时任务保存原始连接，不持有已取消的当前请求上下文。
- 总结工具只提供有边界的聊天资料，不在工具内部再次请求模型。支持最近消息、今日/昨日/本周/近7天；支持话题、决策、行动项和未解决问题。日期查询目前按时间顺序取前若干条，返回范围和截断标记，不能视为整个时间段的完整总结。
- 知识库检索增加常见群聊同义术语归一化，仍是 PostgreSQL 词项检索，不是通用语义搜索。
- `cmd/ai-check` 是可单独运行的真实模型兼容性检查；只发虚构资料，不连接 QQ 或数据库。

## 已确认问题与纠正

1. 临时模型错误原先立即返回不可用；增加有限重试，认证与兼容性错误不重试。
2. 工具协议文本被当正文发送、截断参数仍进入执行；现有故障注入回归覆盖这些症状。
3. 总结工具内部模型请求只有200 token；思考模型可能在生成正文前耗尽。移除嵌套调用，统一输出预算。
4. 初版重构错误删除历史推理，这是本次工作引入的回归，已撤销并建立第二轮400回归测试。不能把它说成已确认的原生产故障根因。
5. 相同工具和参数在同轮会重复执行，现已复用结果。
6. PostgreSQL集成测试实际运行后发现“新人要改什么”无法召回“新成员”规则；分词词项不重合，同义术语归一化后原回归通过。

协议依据：[DeepSeek思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)：携带工具的请求需要回传历史 reasoning_content。SDK保留这些内容用于模型协议，群聊只发送最终 Content。

## 仍未验证的生产条件

- 用户报告那次不可用的原始服务端错误日志尚未取得，不能断言线上唯一根因已经锁定。
- 真实NapCat版本、群消息历史权限、真实QQ收发尚未联调。模拟协议通过不等于生产投递成功。
- 图片模型和各第三方工具服务没有逐一做线上实测；对应能力仍取决于实际配置与上游可用性。
- 日期总结是取样，不能声称读完全部历史。模型仍可能生成错误结论；测试不能保证零故障。
